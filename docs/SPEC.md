# Спецификация: Календарь звонков

Учебное приложение для бронирования встреч.
Владелец публикует типы встреч, гость выбирает свободный слот и записывается на звонок.
Функциональность намеренно ограничена: один владелец календаря, без авторизации и внешних интеграций.

Этот документ — единственный источник продуктового поведения. Технические детали (стек, архитектура, запуск) — в `README.md`, API-контракт — в `packages/spec/main.tsp`.

## Роли

- **Владелец календаря** — один заранее заданный профиль, закреплённый конфигурацией. Регистрации и входа нет: административный раздел (`/owner`) по умолчанию работает от имени этого профиля.
- **Гость** — посетитель, который бронирует слот без создания аккаунта и без входа в систему.

## Use cases

- Владелец календаря (задан заранее, без авторизации) создаёт типы встреч: название, описание, длительность.
- Владелец просматривает список предстоящих встреч всех типов.
- Гость (без регистрации) открывает публичную страницу, выбирает тип встречи.
- Гость видит календарь на ближайшие 14 дней со свободными слотами.
- Гость выбирает слот и подтверждает бронирование.
- Слот занимается — повторно записаться на это время нельзя.

## Rules

### Окно бронирования

- Горизонт бронирования — 14 календарных дней. Значение зафиксировано спецификацией и конфигурацией не настраивается.
- Окно — полуинтервал `[сегодня 00:00, сегодня + 14 дней 00:00)` в часовом поясе владельца: слоты есть в дни от сегодня до сегодня+13 включительно, `windowEnd` — начало 15-го дня (исключительно).
- Окно скользящее: каждый день сдвигается вперёд.
- Начало окна — сегодня (в часовом поясе владельца).
- Бронируемы только слоты, чей старт строго позже текущего момента: прошедшие слоты недоступны, даже если формально попадают в окно.

### Слоты

- Длительность слота = длительность выбранного типа встречи: от 15 до 1440 минут, кратно 15.
- Шаг доступных стартов фиксирован — 15 минут, общий для всех типов. Значение зафиксировано спецификацией и конфигурацией не настраивается.
- Слоты генерируются только в пределах рабочих часов и рабочих дней владельца.
- Конфигурацией задаются часовой пояс владельца, рабочие часы и рабочие дни (см. «Переменные окружения» в `README.md`). Значения по умолчанию: `Europe/Moscow`, `10:00`–`18:00`, понедельник–пятница.

### Занятость

- Пересечение интервалов запрещено, включая частичное наложение разных типов.
- Следующая встреча может начинаться в момент окончания предыдущей.
- Одинаковое время не может быть занято дважды, даже разными типами встреч.
- Правила действуют и для двух одновременных запросов: только один из них получит слот.
- Если гость пытается занять уже занятое время, он видит понятное сообщение о конфликте.

### Отображение времени

- Гостевой календарь отображается в часовом поясе браузера гостя; часовой пояс владельца показывается рядом как справочная информация.
- Часовой пояс владельца определяет «сегодня», границы окна и сетку слотов — независимо от пояса гостя.

## Checkpoints

- Владелец может создать тип встречи (название, описание, длительность)
- Владелец видит список предстоящих встреч всех типов
- Гость видит список типов встреч без регистрации
- Гость видит свободные слоты на 14 дней вперёд
- Слоты генерируются только в рабочие часы и с заданным шагом
- Слоты в прошлом недоступны для бронирования
- Гость видит календарь в часовом поясе своего браузера
- Гость может забронировать свободный слот
- Повторное бронирование того же времени возвращает 409
- Частичное наложение интервалов разных типов запрещено
- Встреча может начинаться ровно в момент окончания предыдущей
- Два одновременных запроса на один слот: один успешен, второй — 409
- Окно бронирования сдвигается с течением времени

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/healthz` | Проверка живости контейнера |
| `GET` | `/meeting-types` | Список типов встреч |
| `POST` | `/meeting-types` | Создать тип встречи |
| `GET` | `/meeting-types/{id}/slots` | Свободные слоты в окне бронирования |
| `GET` | `/bookings` | Предстоящие встречи всех типов |
| `POST` | `/bookings` | Забронировать слот |

Время в запросах и ответах — UTC-инстанты в формате RFC 3339. Свободные слоты приходят вместе с таймзоной владельца и границами окна.

Ошибки возвращаются в едином виде:

```json
{ "code": "slot_not_available", "message": "Slot is not available" }
```

`400` — запрос невалиден: нарушены ограничения полей, включая длительность не кратную 15 минутам и некорректный e-mail. `404` — тип встречи не найден. `409` — старт не является бронируемым: слот занят или пересекается с существующей бронью, находится в прошлом, вне сетки 15 минут, вне рабочих часов или дней либо не помещается до конца рабочего дня.

Авторизации нет ни на одной операции: «владелец» — это раздел интерфейса, а не граница доступа. Следствие, которое нужно учитывать: `GET /bookings` публично отдаёт имена и e-mail гостей. Для учебного проекта это осознанное ограничение, а не недосмотр.

## Вне рамок

Осознанно не входит в продукт:

- регистрация, авторизация, многопользовательность;
- отмена и редактирование бронирований;
- редактирование и удаление типов встреч;
- уведомления (email, SMS);
- интеграции с внешними календарями.
